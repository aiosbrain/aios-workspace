The thesis

Exception handling is not a data problem. It is a queue problem.

Nobody on an operations desk is short of alerts. They are short of an order to work in.

Where the hours go

Eight feeds, one spreadsheet, no order of work

Every exception desk we sat with had the same shape of day.

  • Four inboxes, one human. Carrier EDI, a 3PL portal, an SFTP drop and a shared mailbox arrive in four shapes and land on one coordinator.
  • Alerts fire on movement, not on risk. Six hours late on a fourteen-day lane pages someone. Two hours late before a same-day cutoff does not.
  • Priority is set by whoever shouted. The loudest account gets worked first, so the quiet ones absorb the misses.
  • Nothing survives the shift. The reasoning that resolved yesterday's exception left with the person who resolved it.
Composite of six operations walkthroughs, Q4 2026. Illustrative, and entirely fictional.
Before and after

From a sheet of everything to a queue of four

Same eight feeds either way. The difference is what reaches a person.

Today
  • Everything that moved, ranked by when it arrived
  • Five tabs, two of them forks nobody trusts
  • The reason a row was flagged lives in a comment, or nowhere
With Tideline
  • Four decisions, ranked against the promised date
  • Sixty-two cleared without reaching a person
  • Every card carries the reason it was ranked
How it works

Three stages, one loop

Ingest is boring on purpose. The judgement lives in the middle stage, and the loop is what keeps it honest.

Illustrative. Feed counts, score ranges and volumes are synthetic.
For the people who live in a shell

The same queue, without the browser

Everything the interface does, the CLI did first. It is the same API and the same scoring.

Why a CLI
Because operations already scripts
  • Pipe the queue into whatever you already page from
  • Same auth, same scoring, so there is no second source of truth
  • Replay any rule against last week before you arm it
  • Exit codes a cron job can actually act on
Note. The CLI ships in the same binary as the sync daemon, so there is one version to reason about and one thing to roll back.
